# 라이브 활동지

연수에서 휴대폰으로 함께 쓰는 활동지입니다. 참가자는 휴대폰으로 들어와 활동을 내고, 강사는 노트북의 관리자 화면에서 활동을 열고 닫으며, 프로젝터에는 현황판을 띄웁니다. 연수마다 설정 파일 두 개만 새로 만들면 같은 사이트와 DB를 계속 다시 씁니다.

- 참가자 주소: `https://pblsketch.github.io/live-worksheet/?e=<연수 id>`
- 현황판 주소: `https://pblsketch.github.io/live-worksheet/board.html?e=<연수 id>`
- 관리자 화면: 참가자 주소에서 이름 칸에 관리자 암호를 넣고 들어갑니다.

## 어떻게 이루어져 있나

| 자리 | 하는 일 |
|---|---|
| `index.html`, `board.html`, `assets/` | 정적 사이트(GitHub Pages). 참가자 화면·관리자 화면·현황판 |
| `assets/activities/` | 활동 부품. 지금은 `ox`(사람일까, AI일까?), `stage_check`(몇 단계로 열까?), `sentence`(한 줄 선언) |
| `assets/config.js` | DB 주소와 publishable key(브라우저에 공개되는 키) |
| `events/<id>.json` | 연수 공개 설정(저장소에 올림) |
| `events/<id>.secret.json` | 관리자 암호, OX 정답·해설·패널(**저장소에 올리지 않음**) |
| `supabase/` | DB 표·서버 함수·예약 작업(마이그레이션). 자세한 내용은 [supabase/README.md](supabase/README.md) |
| `tools/` | 등록 명령, 마이그레이션 명령 |
| `materials/shared/` | 여러 연수가 함께 쓰는 자료(9가지 교육적 목적, 설계 루브릭) |
| `tests/` | DB 검사, 단위 검사, 브라우저 E2E |

쓰기는 모두 DB 서버 함수가 검사한 뒤에 합니다. 브라우저는 표에 직접 쓸 수 없습니다. 참가자 이름은 현황판에 보이도록 공개로 읽히고, 연수 날짜에서 30일이 지나면 자동으로 '익명'으로 바뀝니다.

## 처음 한 번: 내 컴퓨터 준비

1. Node 22 이상을 설치하고 `npm install`을 실행합니다. 브라우저 E2E를 돌리려면 `npx playwright install chromium`도 한 번 실행합니다.
2. 저장소 맨 위에 `.env.local` 파일을 만들고 네 줄을 적습니다. 이 파일은 저장소에 올라가지 않습니다.
   ```
   SUPABASE_PROJECT_REF=<프로젝트 ref>
   SUPABASE_URL=https://<프로젝트 ref>.supabase.co
   SUPABASE_PUBLISHABLE_KEY=<publishable key>
   SUPABASE_ACCESS_TOKEN=<Supabase 개인 토큰>
   ```
   개인 토큰은 Supabase 대시보드 → Account → Access Tokens에서 만듭니다. 이 프로젝트에만 쓰도록 범위를 좁혀 두는 것이 안전합니다. 토큰은 채팅·문서·저장소 어디에도 붙여 넣지 않습니다.
3. DB가 비어 있다면 `npm run migrate`로 표와 함수를 만듭니다. 이미 만들어져 있으면 건너뜁니다.

## 새 연수 여는 법

파일 두 개를 만들고, 등록하고, 올리면 끝입니다.

1. **공개 설정** `events/<id>.json`을 만듭니다. `events/bangok1015.json`이나 `events/sample.json`을 복사해 고치는 것이 가장 빠릅니다. 칸마다의 규칙은 [events/README.md](events/README.md)에 있습니다.
   - id는 소문자·숫자·하이픈 3~40자입니다(예: `school1120`).
   - 활동은 적은 순서대로 화면에 나옵니다.
   - 아직 링크가 없는 자료는 `"url": ""`로 두면 "준비 중"으로 보입니다.
2. **비밀 설정** `events/<id>.secret.json`을 만듭니다.
   - OX 활동이 있으면 `reveal.<활동 id>.answers`가 반드시 있어야 합니다.
   - `admin_passcode`를 비워 두면 등록할 때 12자 암호를 새로 만들어 이 파일에 적어 줍니다.
3. **검사**: `node tools/register-event.mjs <id> --dry-run`
4. **등록**: `node tools/register-event.mjs <id>`
   - 다시 등록해도 됩니다. 문구를 고친 뒤 다시 돌리면 설정만 바뀌고, 이미 켠 스위치는 그대로 둡니다.
5. **올리기**: `events/<id>.json`을 커밋하고 푸시합니다. Pages가 1~2분 뒤 새 파일을 내보냅니다. 비밀 파일은 저장소에 들어가지 않게 막혀 있습니다.

`listed: true`인 연수는 주소에 `?e=`가 없을 때 보이는 연수 목록에 나옵니다. 시험용 연수는 `false`로 둡니다.

## 연수 당일 운영

**준비(노트북 한 대, 스크린 한 개)**
- 노트북을 프로젝터에 **확장 모드**로 연결합니다(Windows: `Win + P` → 확장). 청중에게는 프로젝터 화면만 보입니다.
- 노트북 쪽 화면에서 참가자 주소를 열고, 이름 칸에 관리자 암호를 넣어 관리자 화면으로 들어갑니다.
- 슬라이드에 QR과 참가자 주소를 띄우고, 관리자 화면 위쪽의 접속 인원을 봅니다.

**활동 진행**
- 관리자 화면의 활동 카드에서 스위치를 켜면 참가자 휴대폰이 새로고침 없이 활동 화면으로 바뀝니다. 끄면 대기 화면으로 돌아갑니다.
- OX 카드의 **정답 공개** 스위치를 켜기 전에는 정답·점수가 어디에도 나오지 않습니다.
- **자료 전체 공개**를 켜면 활동을 다 내지 않은 사람에게도 자료 메뉴가 열립니다. 끄면 모든 활동을 낸 사람에게만 열립니다.

**현황판 띄우기**
1. 관리자 화면 위쪽에서 보고 싶은 화면의 **모니터에 띄우기**를 누릅니다.
2. 새 창을 프로젝터 화면으로 끌어 옮기고 `F`로 전체화면을 켭니다.
3. `←` `→`(또는 발표 리모컨의 PageUp·PageDown)로 화면을 넘깁니다. 단계 판단 화면에서는 `↑` `↓`로 학습목표 보기를 바꿉니다.
4. 오른쪽 위에 연결 상태(실시간 · 20초마다 새로 고침 · 연결 끊김)가 보입니다.
5. 끝나면 현황판 창을 닫거나 `Alt + Tab`으로 발표 화면에 돌아옵니다.

**리허설 뒤 원래대로 돌리기**
리허설이나 점검으로 들어간 기록은 반드시 지웁니다.
- 관리자 화면 → **응답 모두 비우기**(확인 창을 거칩니다). 참가자와 응답만 지우고 연수 설정은 남깁니다.
- 모든 활동 스위치, 정답 공개, 자료 전체 공개가 꺼져 있는지 확인합니다.

## 새 활동 부품 더하는 법

부품 하나는 네 가지로 이루어집니다: 참가자 화면, 현황판 화면, 관리자 카드 요약, 서버 검사 규칙.

1. `assets/activities/<종류>.js`를 만듭니다. 기존 부품처럼 `participant`, `board`, `adminCard`, `adminResponse`, `adminCell`, `summary`를 내보냅니다. 받는 값(`ctx`)의 모양은 `assets/activities/registry.js` 맨 위 주석에 있습니다.
2. `assets/activities/registry.js`에 한 줄 더합니다.
3. `tools/lib/event-config.mjs`의 `ACTIVITY_TYPES`에 종류 이름을 더하고, 공개 설정 형식 검사를 만듭니다.
4. 새 마이그레이션 파일(`supabase/migrations/000N_….sql`)에 `lw_validate_<종류>` 함수를 만들고, `lw_validate_payload`에 한 줄 더한 뒤 `npm run migrate`를 돌립니다.
5. `events/README.md`에 새 칸을 적고, `tests/`에 검사를 더합니다.

## 비밀 파일과 로컬 접속 정보

| 무엇 | 어디 | 저장소 |
|---|---|---|
| Supabase 개인 토큰, 프로젝트 ref | `.env.local` | 올리지 않음(`.gitignore`) |
| 관리자 암호, OX 정답·해설·패널 | `events/<id>.secret.json` | 올리지 않음(`.gitignore`) |
| 관리자 암호(해시) | DB `lw_event_secrets` | 브라우저에서 읽을 수 없음 |
| DB 주소, publishable key | `assets/config.js` | 올림(브라우저에 원래 공개되는 값) |

관리자 암호를 잊으면 비밀 파일에서 확인합니다. 바꾸려면 비밀 파일의 `admin_passcode`를 고치고 다시 등록합니다.

## 깨우기와 익명화

- **깨우기**: Supabase 무료 프로젝트는 한동안 쓰지 않으면 멈춥니다. `.github/workflows/keepalive.yml`이 사흘마다 가벼운 조회로 DB를 깨웁니다. 매월 1일에는 `.github/keepalive.txt`에 시각을 적어 커밋합니다. 저장소에 60일 동안 변화가 없으면 GitHub가 예약 작업을 끄기 때문입니다. Actions 탭 → keepalive → Run workflow로 수동 실행할 수 있습니다.
- **익명화**: DB 안의 예약 작업(`lw_anonymize`, 매일 한국 시각 03:17)이 연수 날짜에서 30일이 지난 연수의 참가자 이름을 '익명'으로 바꿉니다. 응답(OX 답, 판단과 메모, 선언 문장)은 남깁니다. 메모나 문장 안에 적힌 이름까지는 걸러 내지 않습니다.

## 점검 명령

```
npm run test:db     # 서버 함수 검사 (시험 연수 t-…를 만들고 끝나면 지움)
npm run test:unit   # 현황판 계산(판단 갈림 등) 단위 검사
npm run test:e2e    # 브라우저 E2E: 휴대폰 참가자 흐름, 관리자 스위치, 현황판
npm run snapshot    # DB에 lw_ 아닌 객체가 새로 생기거나 사라지지 않았는지 확인
```

E2E는 저장소를 작은 정적 서버로 띄우고 실제 DB에 시험 연수를 만들었다가 지웁니다. 실제 연수에는 손대지 않습니다.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| "연수를 찾을 수 없습니다" | 주소의 `?e=` 뒤 id가 설정 파일 이름과 같은지, 등록 명령을 돌렸는지 |
| 참가자 화면이 대기에서 안 바뀜 | 관리자 화면에서 그 활동 스위치가 켜졌는지. 학교 와이파이가 실시간 연결을 막으면 20초 안에 다시 불러와 바뀝니다 |
| 현황판 오른쪽 위가 "20초마다 새로 고침" | 실시간 연결이 막힌 망입니다. 20초마다 다시 불러오므로 그대로 써도 됩니다 |
| 현황판이 "연결 끊김" | 노트북 인터넷 연결. 휴대폰 핫스팟으로 바꿔 보고, 안 되면 슬라이드의 백업 장(손 들기·짝 토의)으로 진행합니다 |
| 관리자로 안 들어가짐 | 암호는 대소문자를 구분합니다. 비밀 파일의 `admin_passcode`와 같은지 확인하고, 바꿨다면 다시 등록했는지 |
| 같은 이름으로 들어왔는데 기록이 없음 | "새로 시작"을 누르면 같은 이름의 새 참가자가 됩니다. 이어하기는 같은 이름 가운데 가장 최근에 들어온 기록으로 이어지므로, 앞 기록으로 돌아갈 수는 없습니다. 연수 중에는 "이어하기"를 누르도록 안내합니다 |
| 자료 메뉴가 안 열림 | 모든 활동을 한 번씩 냈는지. 급하면 관리자 화면에서 자료 전체 공개를 켭니다 |
| 등록 명령이 종료 코드 1로 끝남 | 출력된 형식 오류를 고칩니다. DB에는 아무것도 쓰지 않았습니다 |
| 등록 명령이 종료 코드 3으로 끝남 | `.env.local`의 토큰이 만료되었거나 범위가 이 프로젝트를 포함하지 않는지 |
| 한동안 안 쓴 뒤 사이트가 느리거나 DB가 응답 없음 | Supabase 대시보드에서 프로젝트가 멈췄는지(Paused) 확인하고 Restore. Actions의 keepalive가 실패하고 있지 않은지 |
